## Automation and test-data issues resolved

- The first factory password exceeded UI login length limits. Generated passwords now satisfy the login and registration constraints while remaining unique.
- Modern Chromium negotiated documented HTTP QUERY for products/search. Network waits now accept GET or QUERY and exact endpoint paths; the mock intercepts both URL shapes.
- Product headings contain surrounding whitespace. Scoped exact-name patterns normalize that whitespace and escape regex characters.
- The cart identifier is sessionStorage.cart_id, not localStorage.cart. The integration reads the actual UI session identifier.
- Duplicate registration returns the documented 409, and cart item deletion returns the documented 204. Assertions match the OpenAPI contract.
- Backend order validation treats the postcode lookup locality as its source of truth. Test addresses now use that live lookup; a manually chosen real-world city is not equivalent to this demo's synthetic locality.
- Registration and checkout reuse a focused AddressComponent. It waits on an actual lookup when entering new address keys and does not wait for a nonexistent request when keys are already populated.
- The GB lookup returned no state while the UI required one. Routine scenarios now use a US postcode whose demo lookup supplies all required address fields. This change addresses valid-data setup; it does not mask invalid-input scenarios.
- Empty invoice history is a rendered empty table, not a no-invoices message. The test verifies the empty API list and zero tbody rows.
- Guest identity requires opening the Continue as Guest tab. Validation assertions use the actual rendered text.
- The underage error is backend-rendered text rather than a dob-error hook. The test asserts Customer must be 18 years old.
- Successful confirmation uses visible invoice text rather than an unsupported order-confirmation hook. Invoice payment data is nested under payment.
- Profile page readiness now waits for populated email and name fields before edits, preventing the initial account response from overwriting test input.
- Pure API specs use a browser-free fixture; browser diagnostics and cart teardown are limited to UI fixtures.
- ESLint was upgraded from the deprecated 9.x major to supported 10.x after verifying TypeScript-ESLint compatibility.

The public source was consulted only to diagnose observed behavior, after independent browser exploration and test planning: [address consistency rule](https://github.com/testsmith-io/practice-software-testing/blob/main/sprint5/API/app/Rules/AddressMatchesCountry.php), [postcode driver](https://github.com/testsmith-io/practice-software-testing/blob/main/sprint5/API/app/Services/Postcode/FakerPostcodeDriver.php), and [cart rendering](https://github.com/testsmith-io/practice-software-testing/blob/main/sprint5/UI/src/app/checkout/cart/cart.component.html).
